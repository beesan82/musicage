## 意図と理由

MUSICAGE は、レコードプレーヤーの横に立てておく縦型の「文字のオブジェ」になる。所有者が平沢進の歌詞動画に見た魅力、すなわち **歌詞の内容に合わせて書体・組み方・動きが選ばれ、拍に乗って切り替わる** 体験を、置物として成立する静けさの中で再現する。

今の実装は「情景（稜線・霧・光）の上に歌詞を乗せる」作りで、歌詞は静止し、動きは音量にだけ反応している。これを、

- 歌詞と図形が主役、背景シェーダーは質感係
- 行ごとに書体・大きさ・縦横・入り方が変わる
- 音量ではなく拍に乗る
- 「今歌っている行」が本当に同期している

という作りに置き換える。

### 所有者の言葉（そのまま）

- 「視覚的なおしゃれ感、グルーヴ感をもっと高めたい」
- 「平沢のタイポグラフィ動画とかめっちゃおしゃれ」
- 惹かれる点は「歌詞の内容に合わせて、おしゃれなフォント、デザイン、動きで表現されるところ」
- Apple Developer Program は加入済み

## ゴール / 非ゴール / アンチゴール

### ゴール

1. 認識した曲の歌詞が、行単位で本当に同期して表示される（ShazamKit の matchOffset を基準）。
2. 各行に、歌詞の意味に基づいた演出（書体・ウェイト・大きさ・縦横・入り方・滞留中の動き・強調文字）が割り当てられる。
3. 行の切り替わりと強調が、音量ではなく推定した拍に乗る。
4. 曲が分からない時間、歌詞が無い曲、無音の時間も、文字と図形の構成として美しく成立する。
5. 常時表示の作法（画面点灯維持、焼き付き回避ドリフト）を保つ。

### 非ゴール

- 単語単位の同期。行単位で十分とする。行内の文字位置から「今歌っている語」を推定して見せる擬似的な語・音節単位の同期も含む（2026-11-07 改定で明記。第 3 階梯として引き続き採らない）。
- ステージ（シーン）の数を増やすこと。
- Android、横向き、iPad、外部ディスプレイ、翻訳、共有機能。
- 音楽の再生。

### アンチゴール（できても失敗）

- ペット、実績、共有ボタン、点滅演出など、賑やかな要素を足すこと。ここで「点滅」とは、輝度変化が 1 秒に 2 回以上の頻度で繰り返され、かつその振幅が 20% を超えるものをいう（2026-11-07 改定で定義）。ただし音楽に結びついた一過性・条件付きの演出として、(a) 認識確定時の 1 回限りの遷移（ドロップ、§7）、(b) 拍頭のグロー（上限は §5)、(c) サビ相当区間での振幅・グロー・色の上限引き上げ（§4、§5）は認める（2026-11-07 改定）。拍頭で全面が強く光るフラッシュは、頻度・振幅によらず引き続き禁止する。（2026-11-16 改定）ビジュアライザ（§9.1）の拍の閃光も、パターンの要素だけに局所化し、画面平均への寄与に上限を置く条件で、(b) の拍頭のグローと同じ扱いで認める。
- 音量そのもので文字の大きさを直接変えること。行の切り替わりと強調はあくまで推定した拍に乗り、音量（帯域エネルギー）は拍の「乗り」の高さを変える味付けに留める（2026-11-07 改定で明記。第 3 階梯として引き続き採らない）。
- 関係ない行が綺麗に動くこと。同期の確信が無いときは「同期している風」に見せない。
- 音声を端末外に送ること。ShazamKit はフィンガープリントのみ、Claude API には歌詞テキストのみ。
- フォントや演出の種類を増やしすぎて、1曲の中で統一感が失われること。

## 全体構成

```text
iPhone マイク
  -> ネイティブ「耳」モジュール (Swift / Expo Modules API)
       |-- ShazamKit SHSession          -> 認識結果 + matchOffset
       '-- 軽い音響解析 (vDSP)          -> RMS / low / mid / high @ 約50Hz
  -> JS
       |-- 同期時計 (performance.now() 差分で楽曲位置を進める)
       |-- 拍エンジン (オンセット -> テンポ -> 拍位相)
       |-- LRCLIB 同期歌詞
       |-- 演出ディレクター (Claude API で曲ごとに生成、端末にキャッシュ。無ければルールベース)
       '-- 組版エンジン (行 + 演出指示 + 拍 -> Skia 描画命令)
  -> Skia Canvas
       |-- 背景シェーダー (質感のみ: 紙 / グレイン / ビネット / 拍のわずかな明滅)
       '-- 文字・図形レイヤー (Skia テキスト, 縦書きは自前の字送り)
```

マイクを掴むのはネイティブモジュール一つだけにする。expo-audio の録音メーターと AudD の録音は廃止する。これにより認識中にビジュアルが止まる問題も消える。

## 部品ごとの設計

### 1. ネイティブ「耳」モジュール（`modules/expo-musicage-ear/`）

ShazamKit 設計のモジュールを拡張したもの。1つの `AVAudioEngine` 入力タップから、

- `SHSession.matchStreamingBuffer` に音声を流す
- 同じバッファから RMS と 3帯域（目安 low < 200Hz / mid 200Hz–2kHz / high > 2kHz）のエネルギーを計算し、約 50Hz で JS にイベント送出する

JS に渡すもの:

```ts
type EarFeatures = {
  timestampMs: number;     // 端末の単調時計
  rms: number;             // 0..1
  low: number; mid: number; high: number; // 0..1
};

type EarRecognition = {
  trackId: string;
  title: string;
  artist: string;
  album?: string;
  artworkUrl?: string;
  matchedAtMonotonicMs: number;
  currentOffsetMs: number;
};
```

音声バッファ、トークン、生レスポンスは JS に渡さない。

**認識の起動**: 所有者がボタンを押すか、拍エンジンが「無音 → 音あり」の遷移を検出したときに、JS がネイティブへ `listenForMatch()` を要求する。マッチが確定するか 20 秒経ったら ShazamKit への送出を止める（音響解析は止めない）。アプリがフォアグラウンドにある間だけ動く。

**曲の切り替わり**: 同期時計が LRCLIB の最終行を 15 秒以上過ぎた、または無音が 4 秒以上続いて再び音が鳴った場合に自動で再認識する。

### 2. 同期時計

ShazamKit 設計のとおり。`currentOffsetMs + (performance.now() - matchedAtMonotonicMs)` を楽曲位置とし、再認識で上書きする。補正係数は入れない。

### 3. 拍エンジン（`src/beat/`）

純 TypeScript。入力は `EarFeatures`（Expo Go では expo-audio メーターを 60ms 間隔で同形に変換したもの）。

- **オンセット強度**: `low` と `rms` の正の変化量（半波整流差分）を合成。
- **テンポ推定**: 直近 8 秒のオンセット強度列を自己相関し、60–180 BPM の範囲で最大のラグを採る。信頼度（ピークの鋭さ）を 0..1 で出す。
- **拍位相**: 推定周期で位相を進め、強いオンセットで位相を引き込む（単純な位相ロック）。
- **小節頭の推定**: 4 拍周期で `low` のオンセット強度を位相ごとに累積し、最も強い位相を小節頭（ダウンビート）と推定する。推定の信頼が低い間は小節頭なしとし、`bar` は従来どおり 4 拍ごとに数える（2026-11-07 改定）。
- **出力**:

```ts
type BeatState = {
  bpm: number | null;
  confidence: number;      // 0..1
  phase: number;           // 0..1、拍頭で 0
  pulse: number;           // 拍頭で 1 に跳ね上がり指数減衰（アタック即時、減衰 ~250ms）
  bar: number;             // 小節カウント（4/4 仮定）。推定した小節頭から数え、推定できない間は 4 拍ごとに増える（2026-11-07 改定）
  barConfidence: number;   // 小節頭推定の信頼度 0..1（小節頭なしのとき 0）（2026-11-07 改定）
  energy: number;          // rms のゆっくりした追従値
  silence: boolean;
};
```

`confidence` が低い間は `pulse` を弱め、組版は拍ではなく歌詞時刻だけで切り替わる。拍に乗る演出は信頼度が上がってから効く。

### 4. 演出ディレクター（`src/direction/`）

曲ごとに1回だけ、歌詞全体から **曲レベルの指示** と **行ごとの指示** を作る。

#### 語彙（閉じた選択肢）

書体（同梱フォント、OFL ライセンス、6 書体を上限とする）:

| key | 書体 | 役割 |
| --- | --- | --- |
| `mincho` | Shippori Mincho | 文芸、静けさ、夜 |
| `mincho-old` | Zen Old Mincho | 古風、重厚、祈り |
| `gothic` | Zen Kaku Gothic New | 中立、都市、説明 |
| `gothic-heavy` | Dela Gothic One | 叫び、衝撃、見出し |
| `gothic-round` | Zen Maru Gothic | 柔らかさ、幼さ、甘さ |
| `brush` | Yuji Syuku | 筆、土着、祭り |

（具体的な書体の差し替えは実装者に任せる。条件は OFL、日本語常用漢字を収録、合計 40MB 以内。）

行ごとの指示:

```ts
type LineDirection = {
  font: FontKey;
  weight: 'light' | 'regular' | 'bold';
  size: 'xs' | 's' | 'm' | 'l' | 'xl';        // 画面幅に対する相対
  orientation: 'vertical' | 'horizontal';
  entrance: 'cut' | 'drop' | 'rise' | 'scatter' | 'trace' | 'fade'
          | 'print' | 'gather' | 'slide';     // 後ろ 3 つは 2026-11-11 夕 改定で追加
  hold: 'still' | 'pulse' | 'drift' | 'shake' | 'breathe';
  emphasis: number[];                          // 強調する文字のインデックス（最大 3 文字）
  accent: boolean;                             // サビ相当の行か（アクセント色を使い、盛り上がり演出の対象になる）（2026-11-07 改定）
  ornament: 'none' | 'rule' | 'frame' | 'grid' | 'circle' | 'numeral';
  placement?: 'center' | 'top-left' | 'top-right' | 'bottom-left' | 'bottom-right'; // 行の置き場所（省略可、2026-11-11 夕 改定）
};

type SongDirection = {
  palette: { background: string; ink: string; accent: string; accentHigh?: string; light?: string }; // 黒白 + 1 色が基本。サビ相当区間で accent の彩度を上げるための第 2 アクセント（省略可）（2026-11-07 改定）。light は背景の光だまり（灯）の色（省略可、省略時は ink と accent の混合を使う）（2026-11-09 改定）
  texture: 'paper' | 'grain' | 'void' | 'scan';
  tempoFeel: 'still' | 'sway' | 'march' | 'drive';
  idleGlyphs: string;                           // 歌詞の無い時間に散らす記号・数字列
  lines: LineDirection[];                       // LRCLIB の行数と一致
};
```

（2026-11-16 改定）ビルド 15 で足す語彙（入り方・滞留・退場・装飾・ルビ・カメラ・繰り返しの見せ方）は §9.2・§9.3 に置く。

**盛り上がり区間**（2026-11-07 改定）: 「サビ相当」とみなすのは、`accent: true` の行と、音響側の盛り上がり検出（`energy` と `low` の移動平均が曲の上位にある区間）の **どちらか** が立つ区間とする。盛り上がり区間では §5 の振幅・グローの上限と、§6 の色の変化幅を引き上げる。それ以外の区間では通常の上限に戻す。音響だけの判定は遅れと誤検出があるため、`confidence` が低く拍が信頼できない間と、無音明け直後は盛り上がりと判定しない。

#### 生成（Claude API）

- SDK は `@anthropic-ai/sdk`。React Native で動かない場合に限り `fetch` で `POST /v1/messages` を直接叩く。
- モデルは `claude-opus-5-5`。思考はデフォルト（adaptive）のまま、`output_config.effort` は `medium`。
- 構造化出力（`output_config.format`）で上記の JSON スキーマを強制する。
- 入力は曲名・アーティスト・歌詞行配列のみ。音声・時刻・端末情報は送らない。
- 失敗（キー無し・通信失敗・refusal・スキーマ不一致）時は **ルールベース** に落ちる。
- 結果は `trackId` をキーに端末の AsyncStorage/FileSystem にキャッシュし、同じ曲で再リクエストしない。
- 歌詞そのものは保存しない。保存するのは指示 JSON だけ（行テキストは含めない）。

システムプロンプトの要点（実装者が文面を書く）:

- 平沢進の歌詞動画のような、意味に応じた書体と組みの選択。
- 1 曲で書体は 2 種まで、`xl` は曲中 3 行まで、`scatter`/`shake` は連続させない。
- サビや反復行は `accent: true` と `emphasis` を揃えて「決め」を作る。
- 置物として成立する静けさ。賑やかにしない。

#### ルールベース（フォールバック）

歌詞テキストのハッシュで決定的に選ぶ。漢字率が高い行は `mincho`、感嘆符や反復は `gothic-heavy`、短い行は `xl`、長い行は `s` 横書き、など単純な規則で、1 曲の中で書体 2 種に収める。

**出方の選択規則（2026-11-11 夕 改定）。** 所有者の所見「歌詞の出方にパターンが全然なさすぎて面白みがない」を受け、ルールベースでも行ごとの出方に変化と「決め」をつける。すべて歌詞の本文と構造と曲の seed（`アーティスト/曲名`）から決まり、乱数は使わない（同じ曲・同じ歌詞なら同じ演出列）。音量・拍・時刻は材料にしない。

- **新しい入り方（語彙）。** 印刷物・置物の美学の範囲で 3 種を足す。動きの詳細は §5。
  - `print`（刷り上がり）: 一文字ずつ順に、版を押したように少し大きい状態から定位置に収まりながら現れる。字ごとの遅れは固定の短い間隔で、行全体の広がりにも上限がある（行の長さや歌唱時刻に合わせない。擬似的な語・音節同期にしないため）。
  - `gather`（寄せ集め）: 行の外側に散った字が、回転なしで一斉に所定の位置へ寄る。`scatter` が「小さく、回転し、拍でずれて入る」のに対し、`gather` は「遠くから、まっすぐ、同時に」寄る。
  - `slide`（滑り込み）: 字が横（左）から順に滑り込み、行き過ぎずに止まる。縦組みでも横組みでも同じく画面の横方向から入る。
  - 退場は従来どおり入り方から決める: `print` は末尾から消える（`trace` と同じ）、`gather` は散って消える（`scatter` と同じ）、`slide` は右へ滑り去る。
- **置き場所（`placement`）。** 行のまとまり（列・行の外接矩形）を、装飾の分を除いた印刷エリアの中心・四隅のどこに寄せるか。省略時は従来の置き方（縦組みは上寄せ・中央列、横組みは左寄せ・上下中央）。印刷エリアからははみ出さない。前後の行は従来どおり本文の外接矩形を基準に置き、印刷エリアに収める。ルールベースは空でない行すべてに置き場所を与える: 再登場の行は `center`（「決め」は真ん中に置く）、それ以外は四隅と中央を seed と行番号のハッシュで回した順に並べ、直前の表示行と違う最初のものを採る。銘板・歌詞カードの曲名は置き場所を持たない（従来の置き方）。
- **繰り返し行の格上げ。** 同じ本文（前後の空白を除いて一致）が 2 回以上出る行を「反復行」とし、従来どおり全出現で `accent: true`。そのうち **2 回目以降の出現（再登場）** を格上げする: 大きさを 1 段上げる（`xl` は下の予算内でだけ）、装飾は本文から決まる「その行の印」（`frame` か `circle`、同じ本文なら毎回同じ）、滞留は `pulse`、強調文字を最大 3 文字に広げる、入り方は「決め」の候補（`drop` / `gather` / `print`）を優先する。反復の塊（反復行が続く区間）の先頭行は構造的な山とみなし、`xl` の予算を最優先で受け取る。判定は本文の一致と並びだけで行い、音量で大きさを変えることはしない（アンチゴール）。
- **`xl` の予算（曲中 3 行）。** まず再登場の行（塊の先頭が先、次に曲順）に、`xl` で組める長さ（8 字以内）なら配り、残りを従来どおり短い行（4 字以内）に曲順で配る。
- **大小の対比。** 反復でない普通の行が直前の表示行と同じ大きさになるときは、1 段ずらす（長さが許せば上へ、許さなければ下へ。`xl` には上げない、`s` より下へは下げない）。
- **縦横の切り替え。** 英字が過半の行と 20 字を超える行は従来どおり横組み。それ以外は縦組みを基本とし、直前の表示行 2 行が同じ向きなら、14 字以内の行は向きを反転して 3 行連続を避ける。
- **同じ出方を続けない。** 空行を除いた直前 2 行と同じ入り方は選ばない（`scatter`/`shake` の連続禁止は従来どおり）。滞留は直前の行と同じものを避ける。置き場所は上のとおり直前の行と変える（再登場の行の `center` が続く場合を除く）。候補は本文の性格から並べる（感嘆の行は `drop`/`cut`/`slide`、漢字の多い行は `print`/`trace`/`fade`、英字の行は `slide`/`cut`/`rise`、20 字を超える行は `slide`/`print`/`fade` を先頭に。長い行に `scatter`/`gather` は使わない）。その後ろに語彙全体を seed と行番号のハッシュで回した順に並べ、条件を満たす最初のものを採る。

### 5. 組版エンジン（`src/typesetting/`）

入力: 現在行、前後行、`LineDirection`、`SongDirection`、`BeatState`、楽曲位置。出力: Skia に描く文字と図形の配置と各時刻の変形。

- **縦書き**は Skia の `Paragraph` が非対応のため、1 文字ずつグリフを置いて字送りする。長音「ー」、括弧、句読点は回転または位置補正する。
- **入り（entrance）**は行の開始時刻に発火する。`cut` は補間なしで差し替え、`drop`/`rise` はスプリング、`scatter` は文字ごとに拍位相でずらして入る、`trace` は筆順風に左→右（縦なら上→下）に現れる。（2026-11-11 夕 改定）`print` は字ごとに 70ms（行全体の広がりは 900ms まで）ずらして、1.12 倍から等倍へ押されるように 160ms で収まりつつ不透明になる。`gather` は全字が同時に、字ごとに決まった方向へ 90px 離れた位置から回転なしでスプリングで寄る（700ms）。`slide` は字ごとに 30ms（広がり 600ms まで）ずらして、左 56px から行き過ぎない減速で 360ms かけて止まる。退場は `print` が末尾から消え、`gather` が散り、`slide` は右へ 48px 滑りながら消える（いずれも拍のある間は 1 拍以内）。どれも行の一部だけが光ったり全面が明滅したりすることはない。
- **滞留（hold）**は `BeatState.pulse` と `phase` に結び付ける。`pulse` に対してスケールや字間をわずかに動かし、`breathe` は 2 小節周期。
- **拍への整列**: 行の開始時刻が次の拍頭から ±80ms 以内なら拍頭に寄せる。それ以上ずれる場合は歌詞時刻を優先する。
- **前後行**は小さく薄く置く。`xl` の行では前後行を消す。
- **強調文字**は `accent` 色、1 段大きいサイズ、`pulse` に強く反応。拍頭に限って、ぼかした複製によるグローで光らせてよい（2026-11-07 改定）。上限: ぼかし半径 10px 以下、対象は強調文字（最大 3 文字）まで、光り方は拍頭の一過性の減衰に限る。常時グローは置かない（焼き付きと「点滅」化を避ける）。
- **盛り上がり区間**（§4 の定義）では、滞留の振幅・拍頭グロー・`accent` の彩度の上限を引き上げてよい（2026-11-07 改定）。引き上げ幅も含め、「点滅」の定義（アンチゴール）を超える変化はさせない。
- **歌詞が無いとき**（未認識、間奏、曲間。曲が確定して同期歌詞が無いときは下の「銘板」）は、idle を**時計**にする（2026-11-09 改定。所有者の実機判断で、記号・数字列を小節ごとに組み替えるポスターから差し替え）: 時刻 `HH:MM`（24 時間）を大きく、秒 `:SS` を小さく、日付 `M月D日（曜）` を添え、曲名・アーティストを caption に置く。時計は拍ではなく壁時計に従い、無音でも止まらない。変化は毎秒の数字の差し替えだけで、コロンは点滅させない。`idleGlyphs` は演出 JSON に残るが、idle の描画には使わない。（2026-11-11 夕 改定）時計のまま聴いている間も音への反応が見えるよう、印刷エリアの足元に銘板・歌詞カードと同じバンドメーター（同じ位置・本数・色・高さの上限、無音では基線に伏せる、減速表示では基線のまま）を置く。日付行はメーターの上に間隔を空けて収め、メーターと重ねない。曲の舞台（同期歌詞の行・銘板・歌詞カード）に移ると時計のメーターは時計と一緒に消える（銘板・歌詞カードでは同じ場所にそれぞれのメーターが出る）。
- **焼き付き回避**: 既存の `useBurnInDrift` を文字レイヤー全体に適用する。

### 6. 背景シェーダー

既存 5 シーンの SkSL は廃止し、`SongDirection.texture` に対応する 4 種の質感シェーダーに置き換える。各シェーダーは `iPulse`（拍）、`iEnergy`、`iTime` を受け取り、わずかな明滅・粒子・走査線の揺らぎだけを担当する。色は `palette` のみ。

加えて質感シェーダは `iFocus`（主役の行に寄る焦点）、`iLight`（灯の色）、`iLamp`（灯の開き）を受け取り、画面に 1 つの光だまりを描く（2026-11-09 改定）。暗い基調の数値定義: 画面平均 ≤ 22/255、光だまりの中心 ≤ 42/255。拍による持ち上げは光だまり内に限り、絶対値 +5/255 以下とする。なお「背景の平均輝度を変えない」とは、calm / lively の交差で平均を変えないという意味であり、地の絶対値を固定する意味ではない。

質感の種類は 4 種のまま維持し、各シェーダーの内部でエネルギーの高低に応じた見た目の幅（クロスフェード）を持ってよい（2026-11-07 改定）。また盛り上がりに応じて `ink` と `accent`（第 2 アクセントがある場合はそれを含む）を連続に混ぜてよいが、その変化は `iEnergy` のようなゆっくりした追従値に乗せ、振幅はわずかな範囲に留める（背景の平均輝度と黒基調は変えない）。

`styleEngine`（ambient/jazz/pop/dance/rock の判定）は削除する。曲が分からないときの質感は `grain`、パレットはアプリ既定の黒地白文字。

### 7. 画面と操作

- 全画面が組版。タップで薄い操作列を出す（既存の挙動）。
- クローム（ワードマーク・状態・ボタン・設定シート）は、舞台のパレットと同梱書体から導いた色と書体で描く（2026-11-09 改定）。
- 操作列: 「曲を読み取る」、マイクのオン/オフ、設定（Claude API キーの設定・削除、自動再認識のオン/オフ）。
- 曲名・アーティストは組版の一部として小さく常駐する。「同期歌詞」などのラベルは出さない。同期の確信が無いとき（曲が分からない、同期歌詞のある曲の途中で音が途切れた）は行を追わず idle 組版に落ちることで状態を表す。
- 曲は確定したが同期歌詞が無いとき（LRCLIB に時刻つき歌詞が無い、歌詞テキストのみ、インストゥルメンタル）は idle ではなく「銘板」の組版にする（2026-11-09 改定）: 曲名を主役の行として大きく（`pulse` の滞留、かな・漢字を含めば縦組み）、アーティストを小さく、版面の足元に帯域エネルギー（低・中・高の平滑化済み包絡）に従う細い罫の列（バンドメーター）、caption 行に「歌詞が見つかりませんでした」などの短い注記を置く。行も語も追わず、同期を装わない。罫の高さだけが動き、全面の輝度は変えない（アンチゴールの「点滅」「全面フラッシュ」の禁止はそのまま）。歌詞テキストのみ（plain）で本文に刷れる文字があるときは、銘板ではなく下の「歌詞カード」にする（2026-11-10 改定。本文が空白だけの plain は銘板のまま）。
  - 銘板の規則（2026-11-09 夜 改定）:
    - **長い名前。** 曲名は xl → l → m → s と 1 段ずつ下げ、2 列（2 行）まで。s でも 2 列に入らない、または曲名の領域からはみ出す曲名は、入る最長の先頭に「…」を付けて切る（s より小さくしない）。縦組み／横組みの判定は切る前の曲名全体で行う。アーティストは 1 行で、s → xs、xs でも版面の幅に入らなければ同じく「…」で切る。何も版面の外に描かない。
    - **メーターの輝度規律。** 罫の色と不透明度は固定（墨、0.7）で、音で変わるのは高さだけ。高さは基線 3px〜上限 36px にクランプし、帯域値が非数・無限大・範囲外でも上限・基線を越えない。追従は時定数 120ms の一次遅れで、1 フレームの経過時間を 50ms で打ち切る（フレーム落ちの後に跳ばない）。60fps の 1 フレームで罫が動けるのは全行程の約 13%（約 4.3px）まで、毎フレーム全開と無音を繰り返す入力でも揺れは約 2px に収まる。
    - **無音。** 拍エンジンが無音と判定している間（`silence`）は、メーターの目標を 0 にして基線に落とす（環境雑音で帯域値が残っていても）。曲名を含む全グリフの拍駆動の滞留（`pulse`・`shake`・`breathe`）も止まる（無音中もエンジンが保持する拍の格子で、予測拍頭の前の引き戻しが続くのを止めるため。拍に駆動されない `drift` は対象外）。さらに無音が `SILENCE_REARM_MS`（4 秒）続いたら、同期歌詞の行と同じく銘板は idle（曲名の caption つき）に譲り、音が戻ったら同じ曲の銘板に戻る（同じ `trackId` なのでドロップは再発火しない。曲名は通常の `rise` で戻る）。
    - **遷移。** 曲名・行が予定なしに舞台を去るとき（曲の差し替え、見失い、無音）の退場は「今」から始める。新しい曲の結果が確定するまでの 1 レンダーだけ出た idle は、ドロップで散らさずに差し替える（散らすと拍頭まで不透明度 1 で保持され、曲と曲の間に時計がちらつくため）。ドロップの対象になった行・曲名は、舞台がいったん他の行か idle に移ったら、同じものが戻ってきてもドロップで入らない。ドロップの演出（発火時に舞台にあった idle の散り、caption の筆順の描き込み）も再生しない（戻ったときに舞台にある idle は散らさず、曲名の `rise` で替わる）。
- **歌詞カード（plain 歌詞の行を追わない表示、2026-11-10 改定、2026-11-11 改定）。** 曲は確定し、LRCLIB に時刻の無い歌詞テキストだけがあるとき、その本文をレコードの歌詞カード／ライナーノーツのような一枚の刷り物として組む。どの行が今歌われているかは知らないので、知っているふりをしない。
  - **全文一枚（所有者指示、2026-11-11 改定）。** 所有者の言葉（実機所見、そのまま）: 「同期情報のない歌やったら、せめて勝手に送らんと。全部を見えるようにしてよ」。本文は**全文を常に一枚の上に全部見せる**。ページ・ページ送り・巡回・ノンブルは持たない。本文は一度現れたら、退場するまで時間で何も変わらない（切替・送り・スクロール・強調のどれも無い）。**本文を欠落させること（途中で切る、「…」で省く、収まらない分を描かない）と、勝手に送ること（時間・拍・曲の位置で表示を替える）は禁止**。全文表示が仕様である。
  - **アンチゴール（フェイク同期の禁止）。** 本文の表示・強調・色・動きを、拍・小節・エネルギー・帯域・盛り上がり（surge）・推定した曲の位置のどれにも連動させない。現在行の強調（ハイライト、accent、拡大、グロー、前後行の薄め）はしない。本文の色は曲のパレットの `ink` そのもの（surge に追従する墨ではない）、滞留の動きなし、接地影・墨の身体（グラデーション）なし。音楽に反応してよいのは従来どおり舞台の地・灯・質感と、足元のバンドメーターだけ。
  - **構成（銘板の小さい版＋本文）。** 版面の上から: 見出し（曲名を主書体で s の 1 行、アーティストを副書体で xs の 1 行。どちらも入らなければ「…」で切る。見出しの「…」は本文の欠落ではない）→ accent の 12×2 罫（見出しと本文の区切り）→ 本文ブロック（全文）→ 銘板と同じバンドメーター（版面の足元）。caption 行の左に注記「同期情報のない歌詞です」（右のノンブルは 2026-11-11 に廃止）。曲名を大きく出す銘板とは違い、ここでの主役は本文なので、見出しは小さく静かにする（曲名の滞留は `still`。銘板の曲名のような `pulse` はしない）。
  - **組版の規則（`src/typesetting/plainSheet.ts` の純関数）。**
    - 行と段落: 改行で行に分け、各行の前後の空白を落とし、行内の連続した空白は 1 つにする。空行（空白だけの行を含む）は段落の区切りで、何行続いても 1 つの区切り。先頭・末尾の空行は無視。刷れる文字が 1 つも無ければ歌詞カードにしない（銘板）。
    - 縦横: 本文全体にかな・漢字が 1 字でもあれば縦組み、無ければ横組み（銘板の曲名と同じ判定 `titleOrientation`）。縦組みは右の列から左へ列を増やし、`layoutLine` と同じ字の置き方（英数字・長音・括弧は 90° 回し、句読点は右上に寄せる、1 字 = sizePx の正方形のセル）。横組みは行を下へ積む。
    - 折り返し: 行（列）の長さに入らない行は折り返し、2 行目以降は 1 字下げる（元の 1 行の続きだと分かるように）。ラテン文字・数字の語（空白で区切られた英単語）は途中で割らない（語が 1 行より長いときだけ字で割る）。行頭禁則: 、。，．」』）！？ などが行頭に来るときは前の行の最後の語（字）を追い出して一緒に送る。
    - 段落の間は 1 行（列）空ける。段（下記）の頭・末尾が空きになることはない。
  - **収納規則（全文を本文の領域に収める、2026-11-11 改定。`fitPlainBody`）。** 本文の領域は罫の下から、メーターの上の余白までの版面の幅いっぱい。次の順に試し、全文が入った最初のものを採る。
    1. **文字サイズの段階（1 段のまま）。** 大きさ（画面幅に対する比）と行送り（行・列の間隔 = sizePx × 行送り）の組を、大きい順に `PLAIN_SIZE_STEPS` として `plainSheet.ts` の先頭に置く: 0.06（= s）×1.7 → 0.053×1.65 → 0.047×1.6 → 0.041×1.55 → 0.036×1.5 → 0.032×1.45（下限。390pt 幅で約 12.5pt）。大きさは本文全体で 1 つ（行ごとに変えない）。
    2. **下限での段組み。** 下限の大きさで、本文の領域を 2 段、3 段…に分ける（印刷物の歌詞カードの段組み）。縦組みは段を上下に重ね（上段を右から左へ読み終えてから下段）、横組みは段を左右に並べる（左段を上から下へ読み終えてから右段）。段と段の間は sizePx × 1.5（`PLAIN_TIER_GAP`）。1 段の行（列）の長さは sizePx × 8（`PLAIN_MIN_TIER_EM`）を下回らない範囲まで段を増やせる。段数が同じなら、まず段落を段の境で割らない詰め方（段落が 1 段に収まるなら次の段から始める。1 段より長い段落は元の行の境で、1 段より長い 1 行は折り返しの行の境で分ける）を試し、それで入らなければ段落の途中でも段を替えて流し込む。

    - 同じテキスト・同じ画面なら同じ組みになる（決定的）。組み直しはテキスト・画面・書体が変わったときだけで、時間では起きない。
  - **出現（拍とは無関係）。** 本文は歌詞カードが現れてから 1.5 秒後（`PLAIN_BODY_DELAY_MS`、壁時計）に、全文が一度に 1.2 秒（`PLAIN_BODY_FADE_MS`）かけて現れ、以後は退場まで不透明度 1 のまま変わらない。

  - **退場と遷移。** 歌詞カードの見出しの曲名は主役の行と同じ経路で退場する（予定なしの退場は「今」から）。本文は全文のまま 0.4 秒（`PLAIN_EXIT_MS`、固定）でその時の不透明度から消える。アーティスト・罫・メーター・注記は即時に消える（銘板と同じ）。銘板と歌詞カードは別の舞台（曲名の key が違う）として扱い、同じ曲の再解決で plain ⇄ 歌詞なしが替わっても、ドロップは再発火せず、曲名は退場して `rise` で入る。無音 4 秒で idle に譲り音で戻る規則、フィクスチャ優先、1 レンダーだけの idle を散らさない規則、ドロップの対象は 1 回きり、の各規則は銘板と同じ。
  - **書体。** 曲名と本文は主書体、アーティストは副書体、注記は gothic。行の演出が無いので書体は未認識と同じ 2 書体（mincho-old と gothic）になり、1 曲 2 書体の決まりを守る。plain の本文は演出（`directSongByRules`）の材料に使わない（パレット・質感は曲の seed から決まる。行ごとの書体の演出は行を追わない本文には当てない）。
  - **灯。** 灯の中心は本文（全文）の範囲の中心に置く。本文は動かないので灯も動かない。
  - **reduced motion。** 本文のフェードは無く、全文がそのまま出る。本文の退場も無い。
- LRCLIB の答えは、そのセッションのあいだ `trackId` ごとにメモリに覚える（2026-11-09 夜 改定）: 歌詞あり・テキストのみ・インストゥルメンタルの記録も、「無い」という答えも。同じ曲を再認識したとき（自動再認識は音が戻るたびに走る）は LRCLIB に問い合わせない。取得に失敗した（通信・制限・不正な応答・中断）ものは覚えない。端末に保存しない。曲の長さが分かっているときは、`/api/get` の完全一致でも長さが 3 秒より大きく違えば別の録音とみなして検索に回す（長さは比べるだけで送らない）。

#### 9.1 音の見え方のパターン（ビジュアライザ）

現行のバンドメーター（§5 の時計、§7 の銘板・歌詞カードの足元に並ぶ 24 本の罫）を「罫バー」として残し、同じ役目のパターンを 7 つ足す。1 つの舞台に出るパターンは常に 1 つ。

**場所の種類。**
- **足元型**: 版面の足元、今のメーターと同じ帯（全幅、高さ `METER_MAX_HEIGHT`）に収める。時計・銘板・歌詞カードの組版（日付・アーティスト行・本文の領域）は変えない。
- **背面型**: 版面の中、質感シェーダーの上・文字レイヤーの下に描く線画。背面型を出す舞台では足元帯にメーターを出さない。

**パターン一覧（第一陣）。**

| key | 名前 | 場所 | 形と音の対応 |
| --- | --- | --- | --- |
| `bars` | 罫バー（現行） | 足元 | 24 本の 2px の罫。左端が低域・中央が中域・右端が高域。§7 の規律のまま |
| `bars-bold` | 罫バー強化版 | 足元 | 罫を 48 本に。各罫の頭に 2px の刻み（ピーク）が残り、600ms かけて落ちる。キックで低域側の刻みだけが accent に一瞬灯る |
| `wave` | 波形の線 | 足元 | 帯域の包絡から作った 1 本の連続線が、右から左へ流れる（約 3 秒の履歴）。後ろに薄い残像線を 2 本。音声の波形そのものではない（耳モジュールは特徴量しか渡さない） |
| `ripple` | 波紋 | 背面 | キック（低域のオンセット）ごとに、灯の中心から細い輪が 1 本生まれ、広がりながら約 1.6 秒で薄れる。同時に 4 本まで。広がる速さはエネルギーに従う |
| `stipple` | 点描グリッド | 背面 | 版面に等間隔の点（目安 12 × 24）。下の段ほど低域、上の段ほど高域に従って、点の半径が 1〜2.5px で膨らむ。拍ごとに膨らみの波が下から上へ 1 回渡る |
| `curtain` | 縦罫のカーテン | 背面 | 版面の高さいっぱいの細い縦罫（目安 32 本）。エネルギーに応じて、横への揺れが布のように伝わる。拍ごとに揺れの波が 1 つ横切る。罫の長さと明るさは変えない |
| `ring` | 円環スペクトラム | 背面 | 版面の中心の円周に放射状の短い罫（目安 64 本）。下が低域、上が高域で、左右対称。罫の長さが帯域に従う。拍で半径が 2% 以内で呼吸する |
| `landscape` | 音の景色 | 背面 | 下記 |

**音の景色（`landscape`）。** 地平へ向かって、広大な大地を高速で駆け抜けるランドスケープ。初版のモックは所有者に「景色感がない」と却下された。採るのは**前へ進む速度感が主役**の版で、静止した風景画にはしない。
- **構成.** 地平線は版面の下から約 1/3 の高さ。地平線の上には稜線を 3 層（遠・中・近）重ね、視差スクロールさせる（横に流れる速さの目安は、遠 1 : 中 2.5 : 近 6）。地平線の下は地面で、消失点から放射する線と、地平で生まれて手前へ加速しながら流れてくる等高線（透視で間隔が開く）で大地を描く。岩影は地平の中央寄りに小さく現れ、近づくにつれて大きくなり、左右の脇を過ぎて画面の端から出ていく。
- **速度.** 基本の速さはエネルギーに追従する値（時定数 300ms 程度）で、キックごとに一時的な加速（目安 +60%、400ms で減衰）を足す。音が鳴っている間は最低速度を割らない。等高線が地平から下端まで流れる時間は、最も静かな曲でも 3 秒以内、エネルギーが高いときは 0.7 秒前後。岩影の出る頻度も速度に比例し、キックで 1 つ出てよい。
- **見た目.** すべて墨の線画。稜線を地の色で塗って隠線処理するのはよいが、明るい面は塗らない。奥ほど薄くする（目安: 遠の稜線 0.15、近の稜線と手前の等高線 0.45）。
- **無音.** 1.5 秒かけて減速して止まる（景色は残る）。無音 4 秒で舞台が時計に譲る規則は従来どおり。
- **方針との関係.** 「意図と理由」で廃した「情景の上に歌詞を乗せる」作りに戻すものではない。曲ごとに選ばれる 1 つのパターンで、線画で、下の輝度の規律と歌詞優先の減衰に従う。

**曼荼羅（候補。第一陣には入れない）。** 同心の幾何文様が帯域で開閉する案。名前だけ記録し、ビルド 15 では作らない。

**選択規則。**
- 時計（アイドル）と、曲が確定してパターンが決まるまでは `bars`（穏やかな既定）。拍の閃光は使わない。
- 曲が確定したら、その曲の音響特徴から**決定的に 1 つ**選ぶ。材料は拍エンジンと耳の特徴量だけで、テンポ（`bpm`）、エネルギー（`energy`）、低・中・高のバランス（平滑化した帯域の平均の比）、拍の安定度（`confidence` の平均と `bpm` のばらつき）。歌詞と曲名は、候補が複数あるときの割り振り（seed）にだけ使う。
- **観測窓.** 確定後、無音でない時間が 8 秒たまった時点で決める（最長 20 秒。たまらなければ `bars` のまま）。特徴量を粗い段に量子化してから下の表に当て、候補が複数あれば seed（`アーティスト/曲名`、既存の fnv1a）で 1 つに決める。
- **初期の対応表**（上から順に見て、最初に当たった行。閾値は実機で調整）:

| 条件 | 候補 |
| --- | --- |
| テンポが速い（130 BPM 以上）、エネルギーが高い、拍が安定 | `landscape` |
| 低域が優勢、拍が安定 | `ripple` / `bars-bold` |
| 高域が優勢 | `stipple` / `ring` |
| 拍が不安定（リズムの輪郭が緩い） | `wave` / `curtain` |
| テンポが遅い（90 BPM 未満）、エネルギーが低い | `curtain` / `wave` |
| それ以外 | `ring` / `bars-bold` / `bars` |

- **同じ曲なら再認識しても同じ.** 決めたパターンを `trackId` ごとにセッション内で覚え、演出のキャッシュと同じ保存先にパターンのキーだけを保存する（特徴量の値や音声は保存しない）。覚えている曲は観測窓を待たず、最初からそのパターンにする。
- **切り替え.** `bars` から曲のパターンへは、1 回だけ 1.2 秒でクロスフェードする。曲が替わったら（新しい `trackId`）、`bars` に戻ってから同じ手順を踏む。

**舞台ごとの出し方。**
- 時計: `bars`（足元）。
- 銘板: 曲のパターンをそのまま出す。
- 歌詞カード: 本文の読みやすさを優先し、足元型だけ（曲のパターンが背面型なら `bars-bold`）。本文は従来どおり、どの音にも連動しない。
- 同期歌詞の舞台: 曲のパターンを出す（従来はメーターなし）。背面型は不透明度を 0.6 倍にし、主役の行の外接矩形から外側 16px までの範囲には描かない（切り抜き）。

**反応の強さ。** 帯域の読み取りに掛ける係数 `VIZ_GAIN` を、モックの「反応」スライダーと同じ尺度で持つ。現行のバンドメーターの写像はスライダー約 0.45 に相当するので、既定を約 1.15 に上げる（同じ帯域値での振れが約 2.6 倍）。写像の式（線形の倍率か、飽和の手前で寝かせる曲線か）はモックのものを移す。全パターン共通で、時計の `bars` にも掛かる。

**輝度の規律（全パターン共通）。** アンチゴールの「点滅」の定義と、第 3 階梯の全面フラッシュ・ストロボの禁止をそのまま守る。
- 色は墨（surge に追従する ink）と accent だけ。accent は拍の閃光と盛り上がり区間にだけ使う。描くのは線と点だけで、面を明るく塗らない。
- 不透明度の上限は、足元型 0.7（現行）、背面型 0.45。
- 画面平均への寄与は、常時 +3/255 以下、拍の閃光で増える分は +2/255 以下。§6 の暗い基調（画面平均 ≤ 22/255）を超えない。
- **拍の閃光は局所に留める.** 光ってよいのはパターンの要素（刻み、生まれたての輪、点の膨らみ）だけ。1 回の閃光が触れる範囲は画面の 10% 以下で、減衰は拍エンジンの `pulse` と同じ（約 250ms）。§5 の拍頭のグローの延長として扱い、全面を一度に明るくする閃光は作らない。
- 動きは一次遅れで追従させ、1 フレームの経過時間を 50ms で打ち切る（§7 のメーターと同じ）。帯域値が非数・範囲外でも、上限と基線を越えない。
- 無音: 足元型は基線に伏せ、背面型は動きを止める（景色は減速して止まる）。減速表示（reduced motion）では全パターンが静止する。
- 版面の外、ワードマーク行・操作列・caption 行には描かない。UI スレッドだけで動かし、毎フレーム React を再レンダーしない。fps 55 以上。

1. **掛け軸 `kakejiku`（登場）** ← JIZURA `wzKakejiku`
   - 狙う体験: 掛け軸が下ろされ、言葉が上から繰り出される、格のある登場。
   - 動き: 行の塊の上端に accent の 2px の巻棒（両端に小さな軸先）が現れ、下へ転がる。巻棒が通過した所だけ字が見える（クリップの開示。字そのものは動かない）。800ms（拍があれば 2 拍以内）で減速して下端で止まり、巻棒は 200ms で消える。
   - 効かせる場面: 縦組みの行（横組みは複数行の塊だけ）、主書体が明朝系か筆の曲、キメ行。強い動きとして扱う（§9.3）。
   - アンチゴールとの境界: 開示の速さは固定で、歌唱の進みに合わせない（語・音節同期にしない）。光るものは無い。

2. **校正で削る `proof-delete`（退場）** ← `tzProofDelete`
   - 狙う体験: 刷り物の上で、校正者が言葉を削っていく幕引き。「印刷物の上で歌詞が生きる」の芯。
   - 動き: 先頭の字から順に、accent の 1px の斜線（右上 → 左下）が 1 字ずつ引かれる。引かれた字は斜線を残して薄れ、最後に斜線がまとめて 120ms で消える。全体の長さは従来の退場と同じく 1 拍以内（拍が無いときは 480ms）。字数の多い行は、数文字ずつまとめて引く。
   - 効かせる場面: 漢字の多い行や長めの行、印刷や紙の語彙が合う曲。セクションの最後の行に向く。
   - アンチゴールとの境界: 字ごとの遅れは、上限つきの固定の短い間隔で、行の歌唱時間に合わせない。斜線は細く、点滅しない。

3. **呼吸 `breathe`（保持。既存の拡張）** ← `breathe`
   - 狙う体験: 行が「生きてそこに在る」ことの最小の表現。ほかの保持の基準になる。
   - 動き: 既存の 2 小節周期のスケールの呼吸（±1.5% 以内）に、同じ位相の字間の呼吸（字送りの ±4% 以内）を足す。拍が信頼できないときは 4 秒の固定周期。
   - 効かせる場面: 通常の行の保持の基本。長い行、静かな曲。
   - アンチゴールとの境界: 振幅を音量で変えない（盛り上がり区間で上限を引き上げるのは §5 のとおり）。無音では止まる（拍で駆動する滞留の規則に従う）。

4. **風鈴 `furin`（保持）** ← `wzFurin`（保持）
   - 狙う体験: 吊られた紙の短冊が風に揺れる、和の静けさと生命感。
   - 動き: 行の塊の上端中央を支点に、±1.2° 以内の振り子（周期 2.4 秒。拍に縛らない風の揺れ）。支点から版面の上端まで、1px・ink 0.4 の吊り糸を 1 本引く。
   - 効かせる場面: 縦組みで 10 字以内の行、静かな曲、和の書体。キメ行には使わない。
   - アンチゴールとの境界: 揺れは小さく、ぶつかったり跳ねたりしない（`shake` とは別物）。拍で駆動しないので無音でも揺れ続けてよい（`drift` と同じ扱い）。減速表示では止まる。

5. **奥付 `colophon`（装飾）** ← `tyColophon`
   - 狙う体験: 画面の隅に奥付があるだけで、その画面が「刷り物の一頁」になる。
   - 動き: 行の塊と対角にある版面の隅に、gothic xs・ink 0.5 の 3 行（`No. 07` = 曲の中の表示行の通し番号、`12字` = 字数、`縦組・明朝` = 組と書体）を置く。行の登場と同時に 1 字 40ms の固定間隔で印字し、その後は動かない。
   - 効かせる場面: 置き場所が四隅の行（対角の隅が空いている）、組版そのものを見せたい行。1 セクションに 2 回まで。
   - アンチゴールとの境界: 「同期歌詞」などの状態のラベル、時刻、曲の位置は書かない。曲名とアーティストは caption にあるので繰り返さない。

6. **青海波 `seigaiha`（装飾）** ← `seigaiha`
   - 狙う体験: 和文様の代表。紙面の隅が和の地紋に染まる。
   - 動き: 行の塊から最も遠い版面の隅から、同心半円の鱗が 3〜5 段、行の登場の間（600ms）に広がって止まる。線は 1px、ink 0.25（accent の行は accent 0.3）。
   - 効かせる場面: 主書体が明朝系か筆の曲で、キメ行かセクションの頭の行。
   - アンチゴールとの境界: 広がったあとは静止させ、常時の動きにしない。面を塗らない。版面の外に出さない。

7. **字間収束・拡張 `track-in` / `track-out`（登場）** ← `trackIn` / `trackOut`
   - 狙う体験: ほとんど動かないのに、強く「組版」を感じる。最も印刷的な登場。
   - 動き: `track-in` は字間 +0.6em から定位置まで 600ms で収束しながら不透明になる。`track-out` は字間 −0.15em（字が触れる手前）から 500ms で開いて定位置へ。全字が同時に動く（字ごとの遅れは無い）。開いた状態の塊も版面に収まるよう、始めの字間を削る。
   - 効かせる場面: 14 字以内の行。横組みでも縦組みでもよい。通常の行の静かな候補。
   - アンチゴールとの境界: 字の大きさは変えない。音に連動しない。

8. **ルビ振り `ruby`（レイアウト）** ← `tyRuby`
   - 狙う体験: 日本語組版の格を一段上げ、難読の語の読みを静かに示す。
   - 動き: 指定した範囲の親字の上（縦組みは右）に、親字の 0.5 倍の大きさで読み（かな）を置く。行と一緒に登場し、字ごとには動かない。
   - 効かせる場面: **実読みのデータがある行だけ。** データの出どころはフェーズ 3 の Claude 演出（行の中の範囲と読み）で、ルールベースはルビを付けない（推測した読みを刷らない）。
   - アンチゴールとの境界: 読みを時間で塗り進めない（カラオケ式の進行は嘘の同期）。検証器が範囲（行の中にあり、重ならない）と読み（かなだけ）を確かめ、外れたルビは捨てる。

9. **縦罫に畳む `condense`（退場）** ← `tzCondense`
   - 狙う体験: 行が、罫という MUSICAGE の母語に還って幕を引く。
   - 動き: 塊が横方向に中心の 1 本へ縮み（字は潰れながら薄れる）、塊の高さの 2px の墨の縦罫になる。その罫が上下から縮んで消える。1 拍以内（拍が無いときは 480ms）。
   - 効かせる場面: セクションの終わり、縦組みの行。強い動きには数えない。
   - アンチゴールとの境界: 罫は光らない。

10. **拍で呼吸 `beat-breath`（カメラ）** ← `xqBeatBreath`
    - 狙う体験: 舞台全体がわずかに拍で息づき、映像の手触りが出る。
    - 動き: 文字・図形のレイヤー全体を、灯の中心を基点に `1 + 0.008 × pulse` 倍に拡大する（盛り上がり区間は 0.012 まで）。背景シェーダー、ビジュアライザ、クロームは動かさない。焼き付き回避のドリフトとは独立に重ねる。
    - 効かせる場面: 拍の信頼度が 0.5 以上の間だけ効く。セクション単位で付け外しし、行ごとには切り替えない。
    - アンチゴールとの境界: 拍に乗る動きで、音量では変えない（第 3 階梯）。無音と減速表示では止まる。

#### 9.3 ディレクター規則の拡張（JIZURA の構成作法から）

§4「ルールベース」の出方の選択規則に、調査書の「構成作法」から次を足す。決定性（本文・並び・seed だけで決まり、乱数・音量・拍・時刻を使わない）は変えない。Claude 演出（フェーズ 3）の出力にこれらを後処理として掛けるかは、フェーズ 3 の計画で決める。

**セクション。** 歌詞の空行で区切った塊をセクションとする。反復の塊（§4）は、それだけで 1 セクションとみなす。空行の無い歌詞は 8 表示行ごとに区切る。

| 規則 | 調査書の作法 |
| --- | --- |
| セクションのパレットと再利用 | 1. パレットと再利用確率（統一感） |
| 強い動きはキメ行に温存 | 2. 強い動きの抑制、3. キメ行の扱い |
| 繰り返し行の格上げ・完全再現 | 4. 繰り返し行は完全再現 |
| 新奇性の減衰と適合ゲート | 7. novelty と fits |
| 足し算の上限 | 8. typeset の抑制規則 |
| 微細組版 | 9. typesetLine |

1. **セクションのパレット（統一感）。** 各セクションの頭で、スロットごとに使ってよい部品を決め、そのセクションの行はその中からだけ選ぶ。上限は、入り方 3、退場 2、滞留 1、装飾 2（`none` は数えない）、置き場所 3、カメラ 1。新しい部品を毎行出すのではなく、パート内で語彙を揃える（JIZURA の「既出の再利用を優先する」を、頭で決めて固定するパレットで決定的に実現する）。パレットの中身は、そのセクションの行の性格と、下の適合ゲートと、seed で決める。曲全体で使う入り方は 6 種まで。
   - 入り方の上限は JIZURA（2）より 1 多い 3 にする。既存の「直前 2 行と同じ入り方は選ばない」を、パレットの中で満たせるようにするため。
   - 滞留は 1 つに揃えるので、§4 の「滞留は直前の行と変える」はセクションの中では適用せず、セクションが替わるところで変える。
   - キメ行（下記）と、完全再現の再登場はパレットの外。
2. **強い動きはキメ行に温存。** 強い動きは、入り方の `drop` `gather` `scatter` `kakejiku` と、滞留の `shake`。キメ行は、(a) 反復の塊の先頭の行、(b) 再登場の行、(c) 行末が感嘆符（`!` `！`）の行。強い動きはキメ行だけが使い、キメ行の候補（入り方 `drop` / `gather` / `kakejiku` / `print`、装飾 `frame` / `circle` / `seigaiha`、置き場所 `center`）から選ぶ。キメ行が続くときは、2 つ目は強い動きを使わない（完全再現の再登場は除く）。通常の行は静かな部品（`cut` `fade` `rise` `print` `trace` `slide` `track-in` `track-out`）から選ぶ。
3. **繰り返し行の見せ方。** 曲ごとに `repeatMode`（`SongDirection` に任意で足す）を seed で決める。
   - `promote`（格上げ）: §4 の現行の規則（大きさ 1 段上、その行の印の装飾、`pulse`、`center`、強調を広げる、決めの入り方）。
   - `replay`（完全再現）: 再登場は、初出の指示（書体・ウェイト・大きさ・縦横・入り方・滞留・退場・装飾・置き場所・強調・ルビ・カメラ）を寸分違わず再現する。`accent: true` は従来どおり。この曲では、反復の塊の先頭の行の**初出**をキメ行として扱い、`xl` の予算もそこへ配る（再現されるのが「決め」になるように）。再登場はパレット・新奇性・連続回避の規則の対象外。
4. **新奇性の減衰と適合ゲート。**
   - 適合ゲート（fits）: 場面に合わない部品は、候補から先に落とす。`kakejiku` は縦組みか複数行の横組み、`furin` は縦組みで 10 字以内、`track-in` / `track-out` は 14 字以内、`colophon` は四隅の行で対角の隅が空いているとき、`seigaiha` は主書体が明朝系か筆、`ruby` は読みのデータがあるとき、`beat-breath` は 1 セクションに 1 つ。さらに、登場と退場の長さの合計が行の表示時間の 92% を超える部品は落とす（短い行は `cut` / `fade` に寄る）。
   - 新奇性の減衰: 直前 2 表示行で使った部品は重み × 0.2、3〜6 行前で使った部品は × 0.6（滞留・退場・装飾に掛ける。入り方は現行の「直前 2 行と同じものを選ばない」を残し、3〜6 行前に × 0.6 を掛ける）。
   - 組みと入り方の相性: 縦組みは `kakejiku` / `print` / `trace`、横組みは `slide` / `track-in`、四隅の行は `fade` / `rise` / `track-in`、中央の行は `drop` / `gather` / `kakejiku` の重みを上げる（目安 × 1.2〜1.3）。
   - 選び方: 「本文の性格からの順位の重み × 新奇性 × 相性」に、seed と行番号から作る 0.85〜1 の揺らぎを掛け、最大のものを採る（決定的）。
5. **足し算の上限（typeset の抑制）。** 1 行に付ける装飾は 1 つまで（既存の 1 フィールド）。装飾のある行には、ルビ以外の文字の加工（将来足す加工のスロット）を付けない。ルビのある行には `colophon` と `seigaiha` を付けない。拍頭のグローは従来どおり強調文字（最大 3 字）だけ。カメラはセクションに 1 つ、ビジュアライザは舞台に 1 つ。
6. **微細組版。** 部品ではなく、組版エンジン（`layoutLine`）の規則。同期歌詞の主役の行と前後行に掛ける（銘板・歌詞カード・時計は、それぞれの収納規則があるので今回は掛けない）。字送りは送り幅（`advanceMeasure`）に掛け、折り返しと大きさの段は微細組版を掛けた後の実寸で判定する。
   - かなの字送りを詰める: 小さいかな × 0.86、長音「ー」× 0.94、そのほかのかな × 0.90（縦組みは縦の字送り）。
   - 助詞（は・が・を・に・で・と・の・へ・も の 1 字で、前後の字種から判定）は大きさ × 0.78。
   - 行頭の字（漢字・かなで、3 字以上の行）は大きさ × 1.18。
   - ラテン文字は大きさ × 1.08、ラテン文字と日本語の境界に 0.2em の間隔。
   - 強調文字には助詞の縮小を掛けない。行頭の字が強調文字なら、行頭の拡大は掛けない（強調の 1 段上を優先）。
   - 本文から決まる静的な組版で、音量とは関係しない（アンチゴールの「音量で大きさを変える」には当たらない）。

**今回は取り込まないもの（記録）。** 作法 5（前後のカットをつなぐモーフ）、作法 6（太さの成長）、作法 10（歌詞を声より 0.2 秒先に）、作法 11（mood / theme の階層。曲調の判定は §9.1 のビジュアライザ選択だけで使い、歌詞側との共有はフェーズ 3 以降に検討する）。

#### 9.4 設計者の判断（所有者に確かめたいもの）

- 同期歌詞の舞台にもビジュアライザを出す（従来はメーターなし）。背面型は 0.6 倍の不透明度にし、主役の行の周りを切り抜く。
- 反応の強さ 1.15 は時計の `bars` にも掛ける（「穏やか」はパターンの選び方と、拍の閃光を使わないことで表す）。
- 足元型の高さは現行の `METER_MAX_HEIGHT` のまま（時計・銘板・歌詞カードの組版を動かさない）。強化版の強さは本数・ピークの刻み・係数で出す。
- 歌詞カードでは背面型を出さず、`bars-bold` に置き換える。
- パターンのキーを端末に保存する（音声・特徴量の値は保存しない）。
- セクションの入り方の上限を 3 にし、滞留はセクションで 1 つに揃える（§4 の「滞留は直前と変える」をセクションの境に移す）。
- ルビは Claude 演出の読みのデータがある行だけ。フェーズ 3 までは実質的に出ない。

## 進め方（フェーズ）

実機ビルドの往復は遅いので、Expo Go で磨ける部分を先にやる。

1. **タイポグラフィ基盤（Expo Go）**: フォント同梱、組版エンジン、縦書き、6 つの entrance と 5 つの hold、拍エンジン（メーター入力）、質感シェーダー 4 種、idle 組版。開発用に「固定の曲 + LRC + 演出 JSON」のフィクスチャを用意し、偽の同期時計で動かして見た目を詰める。
   - フィクスチャの歌詞は実在曲を使わず、実装者が書いた架空の日本語歌詞（漢字の多い行、短い叫び、英語行、空行を含む 20 行程度）にする。実在曲の歌詞本文はリポジトリに入れない。
   - 開発用コントロールとして、偽時計の開始・一時停止・シーク、演出 JSON の再読み込み、拍エンジンを実マイク入力で回す切り替えを用意する。見た目は偽時計で、拍の乗りは実際に曲を鳴らして確認する。
   - このフェーズの判断は「組版と動きの質」に限る。実在曲での平沢風の到達点はフェーズ 2 の実機同期後に判断する。
2. **Development Build と耳モジュール**: EAS 設定、Swift モジュール（ShazamKit + 帯域解析）、同期時計、自動再認識、AudD と校正系と旧シーンの削除。実機で行単位の同期を確認する。
   - 所有者が行う手順（実装者は代行できない）を先頭に置く: Apple Developer ポータルで App ID（`com.musicage.app`）を作り ShazamKit を有効化、開発用 iPhone の UDID 登録、EAS 初回ビルド時の Apple ログインと証明書生成の承認。Expo アカウント（beesan）はこの PC にログイン済み。EAS プロジェクト（`eas.json`、`projectId`）はまだ無く、このフェーズで作る。（2026-11-08 注記: EAS プロジェクトは作成済み。2026 年 9 月の ShazamKit 版で作られた既存プロジェクト（所有者 `beesan`）を `app.json` の `extra.eas.projectId` に引き継ぎ、`eas.json` は `appVersionSource: remote`。`eas init` は実行しない。`AGENTS.md` と進捗記録の Ruling 9 を参照。）
   - Swift のコンパイルエラーは EAS ビルドログで直す。ビルド往復は 1 回 15〜30 分を見込む。
   - ここで実在曲（平沢進を含む）を鳴らして、同期と演出を所有者が評価する。見劣りするなら方針を見直す。
3. **演出ディレクター**: Claude API 生成、キャッシュ、ルールベースのフォールバック、設定画面。
4. **仕上げ**: 常時表示の作法の再確認、夜間減光、曲間の余韻、パフォーマンス（UI スレッド 60fps 維持）。

各フェーズの終わりに所有者が iPhone で見て判断する。フェーズ 1 の終わりで「見劣りする」なら方針を見直す。

## 受け入れ条件

1. 固定フィクスチャで、行ごとに書体・大きさ・縦横・入り方が指示通りに変わる。
2. 拍エンジンが、合成した 50Hz の `EarFeatures` 列（90–150 BPM のクリック）に対し単体テストで ±3 BPM で追従し、`pulse` が拍頭で立つ。Expo Go のメーター入力（60ms 間隔）では拍は参考値とし、合否は問わない。実機のネイティブ入力ではフェーズ 2 で体感確認する。
3. 実機で、認識から 3 秒以内に歌詞行が出て、以降 1 分間で行の切り替わりが体感 ±0.5 秒に収まる。
4. 曲が終わる／針を上げると idle 組版に戻り、次の曲で自動的に再認識する。
5. Claude キー無しでもルールベースで全機能が動く。キーありでは同じ曲の 2 回目に API を呼ばない。
6. ネイティブ → JS のイベントに音声データが含まれない（型とテストで保証）。
7. 認識中もビジュアルが止まらない。
8. 既存テストのうち残す範囲が通り、型チェックが通る。

## 私（設計者）の判断で決めたこと

所有者に確認していない決定。読んで違えば直す。

- マイクをネイティブモジュール一つに集約し、expo-audio メーターと `react-native-audio-api` は使わない。
- 曲の自動再認識を入れる（アプリがフォアフラウンドの間だけ）。
- 演出の生成は Claude API。モデルは `claude-opus-5-5`、構造化出力、曲ごと 1 回。
- 書体は 6 種上限、1 曲 2 種まで。
- 5 つの音楽ジャンル判定（styleEngine）と既存 5 シーンは全廃。
- 拍は 4/4 固定で小節を数える（2026-11-07 改定で小節頭の推定を導入。拍子そのものは 4/4 固定のまま）。
- フェーズ順はタイポグラフィ先行、ネイティブ後回し。
- フィクスチャは架空歌詞。実在曲での評価はフェーズ 2 に移す。
- 拍エンジンの精度条件は単体テストで判定し、Expo Go の実機では参考値扱い。
