### 判定の物差し

- **候補**: 「紙とインク」の静けさに合い、文字が主役のまま、React Native + Skia のリアルタイム描画（60fps）で再現できるもの。
- **重複**: MUSICAGE の既存語彙（登場 drop / fade / print / gather / slide、配置＝中央＋四隅、装飾 frame / circle / pulse、繰り返し行の格上げ）と実質同じもの。
- **不適合**: Tier 3 アンチゴール抵触（全面フラッシュ／ストロボ、グリッチ、RGB 色ズレ、音量に直接連動した字サイズ、嘘の同期）、世界観の不一致（具象ジオラマ、UI 再現、ポップ、ホラー演出そのもの）、動画書き出し前提の重量処理（全面 blur、全面コピー、パターン生成）のいずれか。
- ホラーパック等でも「仕組みだけが静か」なものは、演出意図を捨てて機構だけ転用する条件で候補に入れ、備考に明記した。

読み方の注意: JIZURA は「カット（歌詞1行の表示単位）」ごとに layout / enter / hold / exit / decor / treat / bg / cam / fx / trans を1つずつ選んで合成する設計。MUSICAGE への移植は部品単位ではなく、この「スロットに1つずつ」という考え方ごと持ってくるのが本質（末尾の「構成作法」節を参照）。

不適合は合計 1,217 件。理由は大きく4つに分かれる。

### 1. Tier 3 アンチゴール抵触

- **全面フラッシュ／ストロボ系**: fx の `strobe`、`flash` 系、enter の `xgStrobe`、`overexpose`、decor の `dateStamp`（フリッカー点灯）など。画面全体の明滅は置物の品位を壊す。
- **グリッチ系**: fx の大半、enter の `glitchIn`、`scramble`、`resolve`、exit の `glitch`、`rgbSplitOut`、layout の `glitchGrid`、`rain`（文字の雨）など。帯ずらし・欠落・ノイズは JIZURA の「乱れ」の美学で、MUSICAGE の静けさとは逆向き。
- **RGB 色ズレ系**: fx の `rgbSplit`、`radialChroma`、treat の `glitchSplit`、`outlineOffset` など。なお単色の「版ズレ」（treat `xoDoublePrint`）は印刷の味として候補に残した。
- **音量に直接連動した字サイズ**: hold の `eqBounce`、`xkLevelFill`、`xkLoudWeight`、cam の `xqLoudZoom` など。エネルギーを字の大きさに直結させる部品は全て落とした（拍連動の微小な動きは候補に残している）。
- **嘘の同期**: treat の `karaoke`、decor の `kzBounceDot` のような色塗り進行は、実同期がない場面では「歌っているように見せる」嘘になる。候補に残した読み位置系（`tyReadCursor` 等）は、同期歌詞が実在する場合にだけ使う前提。

### 2. 世界観の不一致（具象・UI 再現・ポップ・ホラー）

- **具象ジオラマ系レイアウト**（layout の大半）: `xcVending` 自販機、`xcTruck` トラック、`ticket` チケット、`cassette` カセット、`neon` ネオン、`slotMachine` スロット等。歌詞を「物」に載せる発想は、文字そのものが主役の MUSICAGE とは逆。
- **UI 再現系**: decor の x2decC 群（`xnBattery` 電池残量、`xnTicker` ティッカー等）、layout の `xcBrowser`、`searchBar`、`chat`、`notification` 等。画面が「アプリの画面」になってしまう。
- **ポップ／キネティックの激しい動き**: enter の enterB 群（`slingshot` パチンコ、`bounceBig` 等）、exit の x2kineticB 群（`kzBatAway` 打ち飛ばし、`kzCrashApart` 等）、layout の kinetic 群。動きの快楽が主役で、字が道具になっている。
- **ホラー演出そのもの**: horror パックの大半（`hrCctv` 監視モニター、`hzTaken` 攫われる等）。ただし機構だけ静かなもの（緩い呼吸、後ずさり、墨の滴り等）は意図を捨てて候補に転用した。

### 3. リアルタイム描画に重い処理

- **全面 blur / filter 前提**: enter の `blur`、`zoom`、exit の `xjFocusPull`、fx の反転・モザイク系など。フレーム毎の全面ぼかしは Skia でも 60fps を割りやすい。
- **全面コピー・多重描画が本質のもの**: layout の `mirror` 鏡像（反射9回描画）、`tile` 敷き詰め、fx のワープ系など。
- **パターン生成・サンプリング前提**: layout の `dotMatrix`、`mosaicTiles`、`ledScroll` など、オフスクリーンで字をサンプリングして再構成する部品。

### 4. 分類ごとの不適合件数

layout 278 / enter 190 / exit 162 / decor 166 / treat 53 / bg 83 / cam 48 / fx 126 / trans 44 / hold 67（合計 1,217）。fx は分類自体が「全面ポストプロセス」なので不適合率が最も高い（126/138）。逆に treat は safe フラグの文化があり不適合が最も少ない（53/122）。

## JIZURA の構成作法 ― ディレクター規則に取り入れたいもの

部品そのものより価値があるのが、JIZURA が 1,715 部品を破綻なく組み合わせるための「作法」。MUSICAGE のディレクター規則への引き写し案を挙げる。

### 1. セクションごとのパレットと再利用確率（統一感 unify）

- 曲のパート（セクション）ごとに、各スロットの使用パレットを絞る: layout ≤3種、enter ≤2、exit ≤2、hold ≤1、cam ≤2、decor ≤2、treat ≤1。
- パレットが埋まった後は、新規を出すより既出を再利用する確率を 0.75〜0.9 に上げる（sticky picks）。
- **MUSICAGE 案**: 1曲の中で登場・退場・装飾が毎行バラバラにならないよう、「この曲はこの5部品」というパレットを曲頭で決め、行ごとにその中から選ぶ。統一感は部品の質より先に効く。

### 2. 強い動きの抑制（STRONG suppression）

- 強い登場・カメラのリストを持ち、前のカットが強かった場合（または確率 55%）は最大4回まで選び直して弱いものに差し替える。強い動きは「大事な行」のために温存する。
- **MUSICAGE 案**: ドロップ級の強い登場はサビ頭・繰り返し行の格上げ時だけに予約し、通常行は静かな部品から選ぶ二層構造にする。

### 3. キメ行の扱い

- 行末が `!` の行、なければ繰り返しパートの先頭行を「キメ」とし、専用プールから大きなカットを1つ割り当てる。
- **MUSICAGE 案**: 既存の「繰り返し行は格上げ」と接続できる。格上げの手段をサイズだけでなく、キメ専用の登場／レイアウトプールとして定義する。

### 4. 繰り返し行は「完全再現」

- 同じ歌詞行が再び現れたら、初回と完全に同じ構成（レイアウト・登場・退場・つなぎ・モーフまで）を再生する（again / remember の仕様ストア）。
- **MUSICAGE 案**: 現在の格上げ（大きく見せる）に加え、「初回と寸分違わぬ再現」も選べるようにすると、繰り返しの気持ちよさが増す。再現か格上げかは曲ごとに決める。

### 5. 前後のカットをつなぐモーフ

- 同じ行が続く場合、共通する字は滑って移動し、他の字は溶けて入れ替わるモーフでつなぐ。
- **MUSICAGE 案**: 行送り時の字の受け渡しに使える。特に縦書き⇔横書きの `knReflow` 的な組み替えと相性が良い。

### 6. 太さの成長（weightGrow）

- 行の約14%（キメ行では45%）で、細字→太字へ太っていく登場を使う。その際は柔らかい登場（softEnter）に差し替える。
- **MUSICAGE 案**: treat `tzWeightUp` 細字から太字と組で導入できる。「太さ」を行の感情パラメータとして持つ発想。

### 7. 新奇性の減衰（novelty）と適合ゲート（fits）

- 直近6カットの履歴を見て、同じ選択が続くと重みを下げる（直近2回は ×0.2）。逆に字数で使えない部品は fits(n) で事前に落とす。
- レイアウト→登場の相性表（LAYOUT_ENTER バイアス）で、組版に合う登場を寄せる。
- 登場＋退場の合計時間はカット尺の 92% 以下にクランプする。
- **MUSICAGE 案**: ディレクターの選択ロジックに「履歴ペナルティ」「字数ゲート」「レイアウト×登場の相性表」を入れるだけで、ランダム選択の安っぽさが消える。

### 8. 文字整列モード（typeset）の抑制規則

- decor は1カットに最大1つ。decor がある場合は treat を none にする。画面効果は chroma を除き1カットに最大1つ。
- **MUSICAGE 案**: 「足し算の上限」を規則化する。装飾・加工・効果は各スロット最大1つ、という JIZURA の規律はそのまま輸入できる。

### 9. 微細組版（typesetLine）

- かなの字送りを詰める（小さいかな ×0.86、ー ×0.94、その他のかな ×0.90）、ラテン字は ×1.08 に拡大、助詞（はがをにでとのへも、前後の字種で判定）は ×0.78 に縮小、行頭字は ×1.18（漢字・かな、3字以上の行）、ラテン⇔日本語の境界に 0.2em の間隔。
- **MUSICAGE 案**: これは部品ではなく組版エンジン側の規則。既存の advance 計測（実字幅）基盤の上に載せられる、費用対効果が最も高い改善の一つ。treat `tzKanaSmall` かな小組みと合わせて「日本語微細組版」として取り入れたい。

### 10. 歌詞は声より 0.2 秒先に

- JIZURA では歌詞表示をボーカルより 0.2 秒先行させる。
- **MUSICAGE 案**: 同期歌詞の表示タイミングの先行量として検証する価値がある（実同期がある場合のみ。無い場合の先行は嘘の同期になるので不可）。

### 11. おまかせ（mood / theme）の階層

- mood（calm / pop / graphic / editorial / emotional / glitch / horror / chaos）が部品プールと効果量を決め、theme（文字PV／キネティック／和風／ホラー／ポップ／バラード）が使える部品集合をゲートする二層構造。
- **MUSICAGE 案**: 曲調プロファイル（ビジュアライザー選定で導入予定の特徴量ベースの分類）と接続し、「曲調 → テーマ → 部品プール」の階層で歌詞側の演出も選ぶようにすると、音側と字側の演出が同じ曲調判断を共有できる。
